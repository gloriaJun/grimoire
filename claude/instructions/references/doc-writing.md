# 문서 작성 컨벤션

사용자 대상 문서(가이드, 위키, README, 초안, 기술 문서)를 작성할 때 적용한다.
내부 설정 파일(CLAUDE.md, SKILL.md, settings.json 등)에는 적용하지 않는다.
CLAUDE.md의 한국어 산문 규칙(대시 금지, 번역투 회피 등)은 문서에도 동일하게 적용된다.

## 가독성 (기본값 - 요청을 기다리지 않는다)

- 결론 또는 핵심을 먼저 쓴다 (TL;DR 우선).
- 읽기 시작 후 3초 안에 요점이 전달되게 쓴다. 어려운 전문용어는 쉬운 표현으로.
- 한 문장에는 하나만 담는다. 쉼표로 빽빽한 나열 대신 풀어 쓴다.
- 전문용어는 첫 사용 시 한 줄 설명을 붙인다.
- 비교는 표/리스트로 스캔 가능하게 만든다.
- 메타 서술과 자기 언급은 삭제한다.

## 완료/해결된 내용의 기록

끝난 작업이나 해결된 이슈는 미래의 독자에게 필요한 것만 남긴다. 전체 과정은 PR, 커밋, 티켓에 이미 있으므로 재문서화하지 않는다.

- 유지: 근본 원인(1줄), 수정/결과(1줄), 재사용 가능한 교훈(1줄), 참조 링크(PR/커밋/티켓).
- 삭제: 호출 체인 추적, 로그 덤프, 기각된 대안 비교, 단계별 검증 로그.
- 상세 내용은 미해결/후속 작업에만 허용된다.
- TL;DR이 이미 해결 내용을 요약하면 별도의 상세 "해결된 이슈" 섹션을 만들지 않는다.

## 구조 규칙

- 제목에 순번 접두사 금지 (`## 1. 배경` → `## 배경`). 순서는 문서 흐름이 담당한다.
- 구분선(`---`, `***`)을 섹션 구분 용도로 사용 금지. 구조 구분은 제목(`##`, `###`)으로만 한다.
  (표의 구분 행 `|---|---|`은 마크다운 문법이므로 예외.)

## 목차 (TOC)

최상위 섹션(`##`)이 3개 이상일 때만 포함한다.

- 위치: 문서 제목 바로 아래 (도입 문단보다 앞).
- 형식: 앵커 링크가 있는 불릿 리스트.
- `##` 제목이 2개 이하면 목차를 생략한다.
